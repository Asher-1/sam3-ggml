# q8_0 长时多实例回归测试报告（70 帧 × 2 实例，基线）

> 用途：模型 / 代码更新后的质量回归基线。q8_0 与 f16 的逐帧 score/mask 对比数据、
> 复现命令、判定标准。首测日期 2026-09-24（RTX 3060, CUDA, sam3.1 checkpoint）。

## 1. 结论摘要

| 指标 | 结果 |
|------|------|
| PRESENT/ABSENT 翻转 | **0**（两模型逐帧判定完全一致） |
| 轨迹形态 | 完全相同：两实例各 8 帧在场 / 61 帧缺席 |
| both_present 帧 | `|Δscore|` mean **0.020** / max **0.043**；`|Δfg|` 均值 **1.75 px** / max **4 px** |
| both_absent 帧 | `|Δscore|` mean 0.68 / max 19.5（深负数区，见 §4）；fg 恒 0/0 |
| mask 像素 | 全部 138 行无一帧出现"一侧有 mask 一侧无" |

**判定：q8_0 长时跟踪无漂移**。质量敏感场景可放心使用 q8_0（体积 1069 MB，
约为 f16 1866 MB 的 57%；42 帧基准速度 1185 ms/帧 vs f16 1093 ms/帧）。
对照：q4 系列在同场景恢复期 mask 碎裂（fg 掉到 20–106），不可用于本工作负载；
2026-09-28 补测全量化档位（含 q4_K/q6_K，见 §10）后确认 4-bit 族全灭，
q6_K 被 q8_0 支配，两者已删除，**sam3.1 仅保留 f16/q8_0 两档**。

## 2. 环境与资产

- GPU: RTX 3060 12GB（CUDA 后端，`sam3_backend_name` 实测）；CPU 线程 4
- 模型: `models/sam3.1-f16.gguf`（基线）、`models/sam3.1-q8_0.gguf`（被测）
- 视频: `data/test_video.mp4`（14 帧）×5 concat → 70 帧
- runner: `/tmp/track_multi42.cpp`（源码见 §5），每帧打印 `frame inst score fg_px track_ms`
- fg_px = 两个实例 mask 二值化后前景像素数；score = 跟踪器输出分数（>0 视为在场）

视频准备（70 帧测试用 x5 拼接；42 帧用 x3 同理）：

```

/tmp/track_multi42 models/sam3.1-q8_0.gguf 70 /tmp/test_video_x5.mp4 2>/dev/null > /tmp/long70_q8_0.txt

# 稳定性统计（0 翻转 + 在场帧 diff）
for i in 0 1; do
  paste <(awk -v i=$i '$2==i {print $1, $3, $4}' /tmp/long70_f16.txt) \
        <(awk -v i=$i '$2==i {print $3, $4}' /tmp/long70_q8_0.txt) | \
  awk -v i=$i '{
    bothp = ($3+0 > 0 && $5+0 > 0); botha = ($3+0 <= 0 && $5+0 <= 0);
    if (bothp) { p++; s=$5-$3; if(s<0)s=-s; ss+=s; if(s>msd)msd=s;
                 f=$4-$6; if(f<0)f=-f; fs+=f; if(f>mfd)mfd=f }
    else if (botha) a++;
    else { flip++; print "FLIP: frame", $1 }
  } END {
    printf "inst %d: present=%d absent=%d flips=%d | Δscore mean %.3f max %.3f | Δfg mean %.1f max %d\n",
      i, p, a, flip, ss/p, msd, fs/p, mfd
  }'
done
```

## 5. runner 源码（track_multi42.cpp）

```cpp
// Multi-instance per-frame quality tracker.
// Usage: track_multi42 <model.gguf> [n_frames=42] [video=/tmp/test_video_x3.mp4]
#include "sam3.h"
#include <chrono>
#include <cstdio>
#include <cstdlib>
#include <vector>

static const float kPts[][2] = { {315, 250}, {700, 60} };

int main(int argc, char** argv) {
    const char* model_path = argc > 1 ? argv[1] : "models/sam3.1-f16.gguf";
    const int   NF         = argc > 2 ? atoi(argv[2]) : 42;
    const char* video_path = argc > 3 ? argv[3] : "/tmp/test_video_x3.mp4";

    sam3_params params;
    params.model_path = model_path;
    params.use_gpu = true;
    params.n_threads = 4;
    auto model = sam3_load_model(params);
    if (!model) { fprintf(stderr, "TM: load failed\n"); return 1; }
    auto state = sam3_create_state(*model.get(), params);
    sam3_video_params vp;
    vp.hotstart_delay = 0;
    vp.max_keep_alive = 100;
    auto tracker = sam3_create_tracker(*model.get(), vp);

    auto f0 = sam3_decode_video_frame(video_path, 0);
    if (!sam3_encode_image(*state.get(), *model.get(), f0)) return 1;
    int ids[2] = { -1, -1 };
    for (int i = 0; i < 2; ++i) {
        sam3_pcs_params pvs;
        pvs.pos_points.push_back({kPts[i][0], kPts[i][1]});
        pvs.multimask = false;
        ids[i] = sam3_tracker_add_instance(*tracker.get(), *state.get(), *model.get(), pvs, 0);
        fprintf(stderr, "TM: instance %d (id %d) at (%.0f, %.0f)\n", i, ids[i], kPts[i][0], kPts[i][1]);
        if (ids[i] < 0) return 1;
    }

    printf("frame inst score fg_px track_ms\n");
    for (int f = 1; f < NF; ++f) {
        auto frame = sam3_decode_video_frame(video_path, f);
        if (frame.data.empty()) { fprintf(stderr, "TM: frame %d empty\n", f); continue; }
        auto r = sam3_track_frame(*tracker.get(), *state.get(), *model.get(), frame);
        for (size_t k = 0; k < r.detections.size(); ++k) {
            const auto& d = r.detections[k];
            long fg = 0;
            for (uint8_t v : d.mask.data) fg += (v > 127);
            printf("%d %zu %.3f %ld\n", f, k, d.score, fg);
        }
    }
    return 0;
}
```

注意：仓库 `examples/multi_inst_bench.cpp` 是同型 runner（多实例、打印总量），
如需入库版本优先复用它；本 runner 额外输出**逐帧** score/fg，是本报告的数据源。

## 6. 更新模型时的判定标准

对新模型 M 重跑 §3 后，与 f16 基线对比，满足全部条件方可替代 q8_0 作为质量参考：

1. **0 翻转**（任何一帧"基线在场/被测缺席"或反向都算失败）
2. both_present 帧：`|Δscore|` max ≤ 0.05，`|Δfg|` max ≤ 4 px 且无 mask 碎裂
   （碎裂 = fg 掉到 <50% 基线值；q4 系列即死于此条）
3. 恢复帧（缺席→在场切换后的前 3 帧）逐帧检查 —— 4-bit 量化的历史死穴
4. 缺席帧深负数区的 |Δscore| 不设限（饱和区，无行为影响），但要求两侧 fg 均为 0

## 7. 已知问题

- **计时污染**：首测时 f16/q8_0 的 track_ms 列因与其他 GPU 任务并行而不可比，
  已用干净重跑数据替换（见 §8）；质量列（score/fg）是确定性数值，不受影响
- ffmpeg 偶发返回空帧 → runner 需对 frame 0 重试；每次运行必须
  `export PATH=$PWD/data:$PATH`（见 §3）
- 视频 x5 是 `-c copy` 拼接，帧内容与原 14 帧逐位一致，无 re-encode 损失

## 8. 干净计时基线（2026-09-24 重跑，独占 GPU）

| 模型 | 70 帧 × 2 实例平均 track_ms |
|------|------|
| sam3.1-f16  | 1501 |
| sam3.1-q8_0 | 1587（比 f16 慢 5.7%） |

## 9. 130 帧 VRAM 平台期测试（2026-09-24，泄漏修复后）

### 9.1 背景

60 帧回归通过后，首次 130 帧长跑暴露跟踪路径 VRAM **线性泄漏 17.5 MB/帧**
（机器总量 4733→6658 MB / 110 帧，RSS 全程平坦 → 泄漏在设备侧）。

根因：`sam3_encode_memory` 每帧为每个实例克隆 3 个 memenc 槽位 buffer
（sb/sib/speb，f16 下约 15.9 MB/帧）并 `owned_buffers.push_back`，而槽位被
7 槽窗口裁剪后克隆 buffer 永不释放 → 每帧净增 ~16 MB。

修复（所有权下沉）：`sam3_memory_slot.bufs[3]` / `sam3_ptr_slot.buf` 由槽位
自己持有设备 buffer，配合 `sam3_memory_slot_release` / `sam3_ptr_slot_release`
/ `sam3_release_banks` 三个释放助手，在**替换、裁剪、驱逐、rewind 回放、
clear_instance_frame、remove_instance、reset、keep-alive 淘汰**全部路径上释放；
`owned_buffers` 只保留一次性分配。纯生命周期改动，不触碰任何在用数据。

### 9.2 结果（按 PID 采样，排除外部 GPU 进程干扰）

| 指标 | 泄漏构建（旧） | 修复后（本次） |
|------|------|------|
| VRAM（本进程） | 4733→6658 MB，无平台期 | 预热后 **3644 MB 恒定**贯穿剩余 ~105 帧 |
| 增速 | 17.5 MB/帧 | **0 MB/帧**（min=median=max=3644） |
| RSS | 平坦 | 平坦（~0.5-0.8 GB） |

逐样本曲线（每 3 个样本取 1，负载 1876 → 稳态 3448 → 3644 MB 后一字不动）：

## 10. 全量化档位裁定与删除（2026-09-28 补测）

### 10.1 背景

`models/` 曾存在 sam3.1 的 q4_0/q4_1/q4_K/q6_K 四个额外档位（2026-09-23/24
由 `examples/quantize` 从 f16 转出），但从未跑过本报告 §6 的质量判定。
2026-09-28 补齐四个档位的 70f×2 跟踪回归（同 §3 命令，逐帧数据
`/tmp/long70_{q4_0,q4_1,q4_K,q6_K}.txt`），据数据裁定去留。

### 10.2 结果（vs f16 基线，判定标准 = §6）

| 模型 | 大小 | flips | cracks | dScore max | dFg max | 行为描述 |
|------|-----:|------:|-------:|-----------:|--------:|----------|

### 10.3 裁定与执行

1. **q6_K：被 q8_0 严格支配，删除**。GGUF 实测（1622 张量）：q6_K 仅量化
   555 个大权重张量（q8_0 为 600 个），K-quant superblock 元数据 + 多出的
   34 个 F16 fallback 张量吃光收益 —— 文件仅小 8 MB（0.7%），而精度
   （6.56 bpw < 8.5 bpw）与质量（dScore 0.062 > 0.043）全面劣于 q8_0。
   "中间档位"在 60% 张量保持 F32/F16 的转换器现实下退化为伪档位。
2. **q4_K/q4_1/q4_0：跟踪质量死穴，删除**。三者全部碎裂/丢对象，且实测
   严重度与理论精度排序一致（q4_0 > q4_1 > q4_K）—— K-quant 结构救不了
   ViT 权重分布在 4-bit 下的跟踪场景。理论上的"q4_K ≥ q4_1"在真实负载
   上不成立（inst0 上 q4_K 反而多丢 2 帧）。
3. **执行**：4 个文件已从 `models/` 删除（可从 f16 重量化再生，无不可逆
   损失）；HF 仓库从未收录 sam3.1 系列，无需删侧；f16/q8_0 补传 HF 保持
   README 的镜像声明。
